## 1. システム構成

kintoneに登録された送信タイミング（`REMINDER_SCHEDULES`テーブルの各行）を、Google Apps Script（GAS）が定期的に確認し、予定時刻を過ぎた未送信の行にメールを送信します。1レコードに複数の送信タイミングを設定できるため、1レコードから複数通のメールが送られることがあります。

```
kintone (対象アプリ)
   ↓ REST API (GET)
Google Apps Script (時間主導トリガー、既定5分おき)
   ↓ 行ごとに判定・MailAppでメール送信
   ↓ REST API (PUT、行単位)
kintoneへ「送信済み／エラー」を行ごとに書き戻し
```

「今すぐメール送信」ボタンを使用した場合も、kintone側でその時点の未送信の行に即時送信要求を立て、次回のGAS定期実行時にまとめて送信します。

## 2. 前提条件

- kintoneのREST API用にAPIトークンを発行できる権限があること
- 対象アプリが [../CLAUDE.md](../CLAUDE.md) 記載のフィールドコードで作成済みであること
- GASを作成できるGoogleアカウントがあること
- GASからkintoneドメインへHTTPS通信できること
- 送信元はGASを実行するGoogleアカウントとなること

## 3. kintone側フィールドコード

### レコード直下

| 表示名                 | フィールドコード     | 種類             |
| ---------------------- | -------------------- | ---------------- |
| 案件名                 | `TITLE`              | 文字列（1行）    |
| 納期                   | `DEADLINE`           | 日付             |
| メール件名             | `MAIL_SUBJECT`       | 文字列（1行）    |
| メール本文             | `MAIL_BODY`          | 文字列（複数行） |
| 送信先テーブル         | `RECIPIENTS`         | テーブル         |
| 送信タイミングテーブル | `REMINDER_SCHEDULES` | テーブル         |

### `RECIPIENTS`テーブル内

| 表示名         | フィールドコード  | 種類                              |
| -------------- | ----------------- | --------------------------------- |
| 送信先コード   | `RECIPIENT_CODE`  | 文字列（1行）または Lookup        |
| 送信先名       | `RECIPIENT_NAME`  | 文字列（1行）または Lookup        |
| メールアドレス | `RECIPIENT_EMAIL` | 文字列（1行）または Lookup        |
| 送信区分       | `RECIPIENT_TYPE`  | ドロップダウン（`TO`/`CC`/`BCC`） |

### `REMINDER_SCHEDULES`テーブル内（1行＝1つの送信タイミング）

| 表示名         | フィールドコード    | 種類                              |
| -------------- | ------------------- | --------------------------------- |
| 何日前に送るか | `DAYS_BEFORE`       | 数値                              |
| 送信時刻       | `SEND_TIME`         | 時刻                              |
| 送信予定日時   | `SCHEDULED_SEND_AT` | 日時（kintone側で自動算出）       |
| 送信状態       | `SEND_STATUS`       | 文字列（1行）またはドロップダウン |
| 即時送信要求   | `SEND_REQUEST`      | チェックボックス                  |
| 送信日時       | `SENT_AT`           | 日時                              |
| エラー内容     | `ERROR_MESSAGE`     | 文字列（複数行）                  |
| 送信回数       | `SEND_COUNT`        | 数値                              |

**注意**: 表示名ではなく「フィールドコード」がkintone側カスタマイズ・GASコードと完全一致している必要があります。フィールドコードはハードコードされているため（`../src/desktop.js`の`FIELD`、`../gas/src/Config.js`の`FIELD`）、両方を書き換えない限り変更できません。

## 4. kintone APIトークンの発行

1. 対象アプリの「設定」→「APIトークン」を開く
2. APIトークンを生成する
3. 権限「レコード閲覧」「レコード編集」を有効にする
4. 保存後、必ず「アプリを更新」まで実施する
5. 生成したトークンは後述の `KINTONE_API_TOKEN` に登録する

（本カスタマイズは送信先を別アプリのマスタから解決する構成ではなく、対象アプリ1つで完結するため、必要なAPIトークンは1つだけです。）

## 5. Google Apps Scriptプロジェクト作成

```bash
cd customizations/reminder-notify/gas
npm install
npm run build
```

`dist/ReminderMail.gs` が生成されます。

1. Google Apps Scriptを開き、新しいプロジェクトを作成する
2. プロジェクト名を任意に設定する（例：kintone納期リマインド）
3. 「コード.gs」の内容をすべて削除する
4. `dist/ReminderMail.gs` の内容をコピーして貼り付ける
5. 保存する

本方式はGASからkintoneを定期確認する方式のため、右上の「デプロイ」は使用しません。Webアプリ化も不要です。

> 開発者自身がクライアント環境でclaspを使える場合は、[../gas/README.md](../gas/README.md) の手順で複数ファイルのままpushしても構いません。本書は、npm/npx/claspが使えない環境での納品を前提にしています。

## 6. GASタイムゾーン設定

1. GAS左側の歯車アイコン「プロジェクトの設定」を開く
2. タイムゾーンを「(GMT+09:00) 日本標準時 - 東京」または「Asia/Tokyo」に設定する

## 7. スクリプトプロパティ設定

GASの「プロジェクトの設定」→「スクリプト プロパティ」に、以下を登録します（フィールドコードはコードに固定値として組み込み済みのため、スクリプトプロパティへの設定は不要です）。

| プロパティ名         | 必須 | 説明                                                                                                                                                                                                                              |
| -------------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `KINTONE_SUBDOMAIN`  | ○    | kintoneのサブドメイン名（`example.cybozu.com`というURLなら`example`。`.cybozu.com`を含めて設定しても自動補正される）                                                                                                              |
| `KINTONE_API_TOKEN`  | ○    | 手順4で発行したAPIトークン                                                                                                                                                                                                        |
| `KINTONE_APP_ID`     | ○    | 対象アプリのアプリID（アプリのURL `https://example.cybozu.com/k/123/` の `123` の部分）                                                                                                                                           |
| `ADMIN_NOTIFY_EMAIL` | -    | **設定を強く推奨**。認証失敗等、個々のレコードに紐付かないシステム全体のエラーが起きた際の通知先メールアドレス。顧客はGASの実行ログを直接見られないため、未設定だとこの種のエラーに全く気付けなくなる（本書「10. 処理仕様」参照） |

## 8. 手動実行によるメール送信試験

自動トリガーを設定する前に、必ず手動で送信処理が成功することを確認します。

1. 対象アプリでテストレコードを作成し、送信先（`RECIPIENTS`）と送信タイミング（`REMINDER_SCHEDULES`。1行以上）を設定する
2. kintoneの詳細画面で「送信要求を登録」ボタンを押し、対象タイミング・送信先を確認してOKにする（`SEND_REQUEST`が立ち、`SEND_STATUS`が「未送信」のまま更新される）
3. GASのエディタで関数選択欄から `runReminderCheck` を選び、「実行」を押す（初回はGoogleの権限確認画面が表示されるため、内容を確認して許可する）
4. メール受信を確認する
5. 対象行の `SEND_STATUS` が「送信済み」、`SENT_AT` が送信日時、`SEND_COUNT` が加算されていることを確認する
6. `ADMIN_NOTIFY_EMAIL` を設定した場合は、管理者通知メールも一度動作確認しておく。`KINTONE_API_TOKEN` を一時的に別の文字列へ書き換えてから `runReminderCheck` を実行し、`ADMIN_NOTIFY_EMAIL` 宛にエラー通知メールが届くことを確認する。確認後は `KINTONE_API_TOKEN` を元の値に戻すこと

## 9. 自動実行のトリガー設定

手動実行で問題なければ、Apps Scriptエディタの関数選択欄から `setupTrigger` を選んで一度だけ実行します（引数省略時は既定5分間隔。間隔を変えたい場合はコード上で `setupTrigger(1)` のように直接引数を指定して実行する）。

内部で `runReminderCheck` に対する既存トリガーを削除してから作り直すため、間隔を変更したい場合も同じ関数を再実行するだけで構いません。

- **1分間隔**: より予定時刻に近いタイミングで送信できるが、kintoneへのAPIリクエスト数消費が5分間隔の5倍になる
- **5分間隔（既定）**: APIリクエスト数を抑えられるが、予定時刻から最大5分弱の遅延が起こりうる

どちらにするかは、契約プランのAPIリクエスト数上限と、リマインドの時刻精度がどこまで求められるかで判断してください。

## 10. 処理仕様

| 条件                                                             | 動作                                                                                                                                               |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| その行のSEND_STATUS = 未送信 かつ SCHEDULED_SEND_AT <= 現在時刻  | 自動メール送信対象                                                                                                                                 |
| その行のSEND_STATUS = 未送信 かつ SEND_REQUEST = 即時送信        | 次回GAS実行時に即時送信                                                                                                                            |
| 送信成功                                                         | その行のSEND_STATUS=送信済み、SENT_AT更新、SEND_REQUEST解除、SEND_COUNT加算                                                                        |
| 送信失敗                                                         | その行のSEND_STATUS=エラー、ERROR_MESSAGEへ発生日時付きの内容を記録                                                                                |
| SEND_STATUS=送信済み／停止／エラーの行                           | 通常の定期検索では送信対象外                                                                                                                       |
| SEND_STATUS=送信処理中の行が今回の取得時点で既に存在する         | 前回以前の実行が中断された疑いとして検出し、送信対象にはせず`ADMIN_NOTIFY_EMAIL`宛に通知（本来は同一実行内で必ず送信済み／エラーへ解消されるため） |
| レコード取得失敗・認証失敗等、行に紐付かないシステム全体のエラー | `ADMIN_NOTIFY_EMAIL`宛にメール通知（未設定時はGASの実行ログにのみ記録）                                                                            |
| エラー状態への書き戻し自体が失敗（行が処理中のままスタック）     | 同上（行のSEND_STATUSは変化しないため、この通知が無いと気付く手段が無い）                                                                          |

送信済み・エラーの行を含むレコードを編集して保存しても、**その行の送信予定日時（`SCHEDULED_SEND_AT`）が実際に変わらない限り**送信状態は維持されます（無関係な項目を直しただけで送信履歴が消えたり、意図せず再送信されたりしないようにするための仕様）。送信タイミングを変えずに（例: `RECIPIENT_EMAIL`の誤りだけを直して）再送信したい場合は、`SEND_STATUS`（ドロップダウン）を手動で「未送信」に変更して保存してください。

保存時には、`REMINDER_SCHEDULES`が空、`RECIPIENTS`に有効な送信先が1件も無い、または区分「TO」の送信先が1件も無い場合にエラーになります。

**個々の行のエラーと、管理者通知メールの違い**: `RECIPIENT_EMAIL`の形式ミスなど、特定のレコード・行に原因があるエラーはその行の`SEND_STATUS`=エラー・`ERROR_MESSAGE`としてkintone上に表示されるため、顧客が直接確認できます。一方、APIトークン失効やkintone側の一時的な障害など、システム全体に影響する（＝どの行にも原因を書き戻せない）エラーは、`ADMIN_NOTIFY_EMAIL`宛のメールでしか気付けません。**`ADMIN_NOTIFY_EMAIL`は必ず設定し、手順8-6で一度動作確認してください。** 同じ障害が続く間は1時間に1通までしか送られません（トリガー(既定5分おき)のたびに大量送信されるのを防ぐため）。

## 11. 主なエラーと確認項目

| エラー／症状                                                                               | 主な原因                                                                                                                     | 対応                                                                                                                                               |
| ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| HTTP 403 / GAIA_AP15                                                                       | アプリIDとAPIトークンの組み合わせ不一致                                                                                      | スクリプトプロパティの`KINTONE_APP_ID`と`KINTONE_API_TOKEN`が同じアプリのものか確認。アプリ更新も確認                                              |
| HTTP 400 / CB_IL02                                                                         | クエリが不正、またはGETにContent-Typeヘッダーを付けている                                                                    | 配布コードでは修正済み（クエリのグループ化・GETのヘッダーとも対応済み）。改造した場合は要再確認                                                    |
| HTTP 400 / CB_VA01 / 必須項目エラー                                                        | 既存レコードの必須項目が空                                                                                                   | 対象レコードの必須項目を入力して保存する                                                                                                           |
| 「メールアドレスの形式が不正な送信先があります」                                           | `RECIPIENT_EMAIL`の形式ミス                                                                                                  | 対象レコードの送信先メールアドレスを修正する                                                                                                       |
| 「本日のメール送信可能数が不足しています」                                                 | GAS実行アカウントの1日のメール送信上限に到達                                                                                 | 翌日以降に再試行、または送信数を見直す                                                                                                             |
| 「送信区分「TO」の送信先メールアドレスが登録されていません」                               | TO区分の送信先のメールアドレスが未入力（区分自体が1件も無い場合は保存時にkintone側で弾かれるため、通常はこのケースのみ発生） | 送信先テーブルのTO区分の行にメールアドレスを入力する                                                                                               |
| 予定時刻になっても送られない                                                               | トリガー未設定、トリガー失敗、SCHEDULED_SEND_ATが未来、SEND_STATUSが未送信でない                                             | GASの「トリガー」「実行数」（実行ログ）を確認する                                                                                                  |
| 9時間程度ずれる                                                                            | UTC/JSTの解釈差                                                                                                              | GASタイムゾーンをAsia/Tokyoに設定し直す                                                                                                            |
| 対象レコードが編集できなくなった（「現在メール送信処理中の行があるため、編集できません」） | 送信処理の途中でGASの実行が異常終了し、行が「送信処理中」のまま残った(まれ)。`ADMIN_NOTIFY_EMAIL`宛に自動で通知される        | 実際にメールが送信されたか受信箱を確認したうえで、kintoneの管理者権限で該当行の`SEND_STATUS`を直接修正する（二重送信防止のため自動では復旧しない） |

## 12. セキュリティ・運用上の注意

- APIトークンをソースコードへ直接記載せず、GASのスクリプトプロパティへ保存する
- APIトークンをメールや公開資料へ記載しない
- 本方式ではGASをWebアプリとして公開しないため「デプロイ」は不要
- 5分（または設定した間隔）のトリガーでも、予定時刻ちょうどの厳密な送信は保証されない
- GASがメール送信した直後にkintoneへの書き戻しだけ失敗した場合、二重送信防止の観点から自動再送はしない。実際の受信状況を確認したうえで状態を修正すること（上記11の最終行を参照）
- 同じ関数(`runReminderCheck`)のトリガーを複数作ると二重実行の原因になる。トリガー作成・変更は必ず`setupTrigger`関数経由で行う
