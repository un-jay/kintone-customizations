# reminder-notify 個別仕様

全体共通の開発方針は [ルートのCLAUDE.md](../../CLAUDE.md) を参照。ここには本カスタマイズ固有の仕様のみを記載する。GAS側の仕様は [gas/README.md](./gas/README.md) を参照。

## 機能概要

1件の納期に対して**複数の送信タイミング**（例: 7日前・3日前・前日）を設定できるリマインド通知。「納期」と、`REMINDER_SCHEDULES`テーブルの各行の「何日前に送るか」「送信時刻」から、行ごとに送信予定日時を自動算出し、kintone側でレコードを準備する。実際のメール送信はGoogle Apps Script（[gas/](./gas/)）が時間主導型トリガーで定期的にkintone REST APIを確認し、行ごとに送信予定日時が到来したものへ行う（1行＝1通のメール）。kintone側カスタマイズは以下を担当する。

- 行ごとの送信予定日時の自動算出
- 保存時のバリデーション（送信先1件以上、送信タイミング1件以上、日時算出エラー）
- レコード詳細画面からの即時送信リクエスト登録（未送信の行をまとめて対象にする）

## 対象アプリのフィールドコード（固定）

本カスタマイズは、複数アプリでの再利用よりもシンプルさを優先し、フィールドコードを`src/desktop.js`の`FIELD`定数に固定値として持つ。対象アプリは、以下のフィールドコードで作成する必要がある（GAS側`gas/src/Config.js`の`FIELD`定数も同じ値で定義しており、両者は必ず一致させること）。

フィールドコードは、リポジトリ全体の命名規則（[ルートのCLAUDE.md](../../CLAUDE.md#コーディング規約)参照）に合わせ、SCREAMING_SNAKE_CASE（例: `RECIPIENT_CODE`）で統一する。

### レコード直下

| フィールドコード     | 型               | 説明                                       |
| -------------------- | ---------------- | ------------------------------------------ |
| `TITLE`              | 文字列（1行）    | タイトル                                   |
| `DEADLINE`           | 日付             | 納期                                       |
| `MAIL_SUBJECT`       | 文字列（1行）    | メール件名                                 |
| `MAIL_BODY`          | 文字列（複数行） | メール本文                                 |
| `RECIPIENTS`         | テーブル         | 送信先一覧                                 |
| `REMINDER_SCHEDULES` | テーブル         | 送信タイミング一覧（1行＝1回のリマインド） |

### `RECIPIENTS`テーブル内

| フィールドコード  | 型                                | 説明                 |
| ----------------- | --------------------------------- | -------------------- |
| `RECIPIENT_CODE`  | 文字列（1行）または Lookup        | 送信先コード         |
| `RECIPIENT_NAME`  | 文字列（1行）または Lookup        | 送信先名             |
| `RECIPIENT_EMAIL` | 文字列（1行）または Lookup        | 送信先メールアドレス |
| `RECIPIENT_TYPE`  | ドロップダウン（`TO`/`CC`/`BCC`） | 送信区分             |

送信先名・送信先メールアドレスは、別アプリ（送信先マスタ等）からのLookupフィールドとして構成しても問題ない。`record[フィールドコード].value`で値を参照するだけなので、通常の文字列フィールドかLookupフィールドかを区別しない。

### `REMINDER_SCHEDULES`テーブル内

| フィールドコード    | 型                                | 説明                                                             |
| ------------------- | --------------------------------- | ---------------------------------------------------------------- |
| `DAYS_BEFORE`       | 数値                              | 何日前に送るか                                                   |
| `SEND_TIME`         | 時刻                              | 送信時刻                                                         |
| `SCHEDULED_SEND_AT` | 日時                              | この行の送信予定日時（自動算出）                                 |
| `SEND_STATUS`       | 文字列（1行）またはドロップダウン | この行の送信ステータス（未送信/送信処理中/送信済み/エラー/停止） |
| `SEND_REQUEST`      | チェックボックス                  | この行の即時送信要求                                             |
| `SENT_AT`           | 日時                              | この行の送信日時                                                 |
| `ERROR_MESSAGE`     | 文字列（複数行）                  | この行のエラーメッセージ                                         |
| `SEND_COUNT`        | 数値                              | この行の送信回数                                                 |

ステータス文言（未送信/送信処理中/送信済み/エラー/停止）と即時送信要求の値（`即時送信`）は`desktop.js`内の固定値。

**注意（kintone REST APIのクエリ制約）**: kintoneのクエリは、サブテーブル内の複数フィールド条件をANDで組み合わせても「同じ行が両方の条件を満たす」ことまでは保証しない（別々の行がそれぞれの条件を満たしていてもヒットする）。そのためGAS側では、このクエリを「候補レコードの粗い絞り込み」としてのみ使い、実際にどの行が送信対象かは取得後にアプリケーション側（`pickDueScheduleRows`）で行単位に再判定する。詳細は[gas/README.md](./gas/README.md)を参照。

## メール本文・件名のプレースホルダ

`MAIL_SUBJECT`/`MAIL_BODY`内の`{{フィールドコード}}`は、送信対象レコードの値に置換される。`{{DAYS_BEFORE}}`/`{{SEND_TIME}}`/`{{SCHEDULED_SEND_AT}}`は、送信対象になった**その行**の値に置換される（1通のメールは1つの送信タイミング行に対応するため）。

## 送信ステータスの状態遷移（行ごと）

```
未送信 → (GASが送信予定日時到来を検知/即時送信要求) → 送信処理中 → 送信済み
                                                                  ↘ エラー
```

- `REMINDER_SCHEDULES`のいずれかの行が送信処理中のレコードは編集不可（`app.record.edit.submit`でエラーにする）
- 送信済み・エラーの行を編集して保存しても、**その行の送信予定日時（`SCHEDULED_SEND_AT`）が実際に変わらない限り**、送信ステータス・送信日時・エラー内容は維持される。無関係な項目（メール本文の誤字修正等）を直しただけで保存した場合に、送信済みの履歴が消えたり意図せず再送信対象に戻ったりしないようにするための挙動（`app.record.edit.submit`で保存前後の`SCHEDULED_SEND_AT`を比較して判定する）
- 送信予定日時が実際に変わった行だけ、未送信に戻り（`SENT_AT`/`ERROR_MESSAGE`もクリアされ）再度送信対象になる
- 停止は、GAS側の対象抽出条件から除外するための状態（手動で設定する想定。UIからの遷移は持たない）
- 「今すぐメール送信」ボタンは、レコード内で現在「未送信」の行をすべてまとめて即時送信対象にする（行ごとのボタンは、kintoneのテーブル内部DOM構造に依存することになるため設けない）

## APIリクエスト数について

- kintone側カスタマイズ自体は、即時送信ボタン押下時にレコード更新PUTを1回発行するのみ
- GAS側の定期実行によるREST API呼び出し回数は [gas/README.md](./gas/README.md) を参照（1レコードに複数の送信対象行がある場合、行の数だけレコード更新PUTが発生する点に注意）
