# reminder-notify (GAS側)

reminder-notify kintoneカスタマイズと組み合わせて使う、Google Apps Script（GAS）側の実装です。時間主導型トリガーで定期的にkintoneをチェックし、送信予定日時が到来したレコード・即時送信要求のあるレコードにリマインドメールを送信します。

kintone側カスタマイズの仕様（対象アプリのフィールドコード一覧を含む）は [../CLAUDE.md](../CLAUDE.md) を参照してください。**フィールドコードはkintone側・GAS側の両方で固定値**として実装しているため、対象アプリはそのフィールドコードで作成する必要があります。

## 構成

| ファイル                 | 責務                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `src/Config.js`          | スクリプトプロパティからの機密情報読み込み、固定フィールドコード定義 |
| `src/KintoneClient.js`   | kintone REST APIの呼び出し（対象レコード取得・レコード更新）         |
| `src/Mailer.js`          | メール送信・件名/本文のプレースホルダ置換                            |
| `src/ReminderService.js` | 対象抽出→送信→結果書き戻しの業務ロジック                             |
| `src/Main.js`            | 時間主導型トリガーのエントリポイント、トリガーのセットアップ関数     |

## 処理の流れ

1. `runReminderCheck()` がトリガーにより実行される
2. `(送信ステータス = 未送信 かつ 送信予定日時 <= 現在時刻)` または `即時送信要求あり` のレコードをkintone REST APIで取得（$id昇順のseek法で501件目以降にも対応）
3. レコードごとに、送信ステータスを「送信処理中」に更新（多重実行防止）
4. 送信先テーブルの各行を「送信区分」（`TO`/`CC`/`BCC`。未設定・不明な値は`TO`扱い）で振り分け、1通のメールとしてまとめて送信（件名・本文は `{{フィールドコード}}` 形式のプレースホルダをレコード値に置換）。TO区分の送信先が1件もない場合はエラーとして扱う
5. 成功: 送信ステータスを「送信済み」に、送信日時・送信回数を更新
6. 失敗: 送信ステータスを「エラー」に、エラーメッセージを更新

## セットアップ手順

### 1. Apps Scriptプロジェクトの作成

```bash
cd customizations/reminder-notify/gas
npm install
npx clasp login
npx clasp create --type standalone --title "reminder-notify" --rootDir ./src
```

`clasp create` 実行後に生成される `.clasp.json`（`scriptId` を含む）は、`.gitignore` により追跡対象外です。`.clasp.json.example` を参考に、必要であれば手動で `.clasp.json` を作成してください。

> **既知の注意点**: 環境によっては`clasp create`が`.clasp.json`を`gas/`直下ではなく`gas/src/`の中に生成することがあります。その場合は`gas/src/.clasp.json`を`gas/`直下へ移動してください（`rootDir`の値はそのままで問題ありません）。

### 2. スクリプトプロパティの設定

Apps Scriptエディタの「プロジェクトの設定」→「スクリプト プロパティ」で、以下の**機密情報のみ**を設定します（フィールドコードは`src/Config.js`に固定値として定義済みのため、スクリプトプロパティへの設定は不要です）。

| プロパティ名        | 説明                                                                                                                                                                  |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `KINTONE_SUBDOMAIN` | kintoneのサブドメイン名のみ（例: `example.cybozu.com`というURLなら`example`。`.cybozu.com`は含めない。含めてしまっても`.cybozu.com`が二重に付かないよう補正はされる） |
| `KINTONE_API_TOKEN` | kintoneアプリのAPIトークン。「レコード閲覧」「レコード編集」権限が必要                                                                                                |
| `KINTONE_APP_ID`    | 対象アプリのアプリID                                                                                                                                                  |

### 3. デプロイ

```bash
npm run push
```

### 4. まずは手動実行でテスト（トリガー不要）

Apps Scriptエディタで`runReminderCheck`関数を選んで実行してください。初回は権限の承認が求められます。即時送信要求が立っているレコードがあれば、この時点で処理されます。

### 5. 自動実行のトリガーを設定

手動実行で問題なければ、`setupTrigger`関数を一度だけ実行します（引数省略で既定5分間隔）。

```js
setupTrigger(5); // 5分間隔
```

内部で `runReminderCheck` に対する既存トリガーを削除してから作り直すため、間隔を変更したい場合も同じ関数を再実行するだけで構いません。

## 既知の制約

- Google Apps Scriptの1回の実行時間上限は6分です。対象レコード数が多い場合は、トリガー間隔や抽出条件を調整してください。
- `UrlFetchApp`・`MailApp` にはGoogleアカウントの1日あたりのクォータがあります（[Apps Scriptの割り当て](https://developers.google.com/apps-script/guides/services/quotas)を参照）。
- トリガー間隔は、kintoneのAPIリクエスト数上限を考慮し、短くしすぎないでください（既定5分)。詳細は[ルートのCLAUDE.md](../../../CLAUDE.md#apiリクエスト数について)を参照。
