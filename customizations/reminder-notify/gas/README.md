# reminder-notify (GAS側)

reminder-notify kintoneカスタマイズと組み合わせて使う、Google Apps Script（GAS）側の実装です。時間主導型トリガーで定期的にkintoneをチェックし、`ReminderSchedules`テーブルの各行（1行＝1つの送信タイミング）のうち、送信予定日時が到来した行・即時送信要求のある行にリマインドメールを送信します。1レコードに複数の送信タイミングがある場合、行の数だけメールが送信されます。

kintone側カスタマイズの仕様（対象アプリのフィールドコード一覧を含む）は [../CLAUDE.md](../CLAUDE.md) を参照してください。**フィールドコードはkintone側・GAS側の両方で固定値**として実装しているため、対象アプリはそのフィールドコードで作成する必要があります。

## 構成

| ファイル                 | 責務                                                                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/Config.js`          | スクリプトプロパティからの機密情報読み込み、固定フィールドコード定義                                                                                        |
| `src/KintoneClient.js`   | kintone REST APIの呼び出し（対象候補レコード取得・行単位のレコード更新）                                                                                    |
| `src/Mailer.js`          | メール送信、件名/本文のプレースホルダ置換、送信先メールアドレスの形式チェック・送信可能数チェック、システム全体のエラーの管理者通知(`notifyAdminOnFailure`) |
| `src/ReminderService.js` | 対象抽出（行単位の再判定）→送信→結果書き戻しの業務ロジック                                                                                                  |
| `src/Main.js`            | 時間主導型トリガーのエントリポイント（多重実行防止）、トリガーのセットアップ関数                                                                            |

## 処理の流れ

1. `runReminderCheck()` が1分間隔のトリガーにより実行される。設定した実行間隔（既定5分）の倍数の分（毎時00分/05分等）でなければ、kintoneへアクセスせず即座に終了する（`isAlignedMinute`）。該当する場合は`LockService`で多重実行を防ぐため、前回の実行がまだ終わっていなければ何もせず終了する
2. `(送信ステータス = 未送信 かつ 送信予定日時 <= 現在時刻)` または `即時送信要求あり` または `送信ステータス = 送信処理中` の**候補レコード**をkintone REST APIで取得（$id昇順のseek法で501件目以降にも対応。「送信処理中」は3の中断検知に使うだけで、送信対象にはしない）
3. 候補レコードごとに、`ReminderSchedules`テーブルの行を1件ずつ確認し、実際に条件を満たす行だけを送信対象として抽出する（**注意**: 手順2のクエリはサブテーブルの複数フィールド条件のANDで「同じ行が両方満たす」ことまでは保証しないため、あくまで粗い絞り込み。行単位の最終判定は取得後にアプリケーション側で行う）
4. 送信対象の行ごとに、その行の送信ステータスを「送信処理中」に更新
5. 送信先テーブルの各行を「送信区分」（`TO`/`CC`/`BCC`。未設定・不明な値は`TO`扱い）で振り分け、1通のメールとして送信（件名・本文は `{{フィールドコード}}` 形式のプレースホルダを、レコード値およびその送信タイミング行の値（`DaysBefore`/`SendTime`/`ScheduledSendAt`）に置換）。送信前に、メールアドレスの形式チェックと本日の送信可能数チェックを行う。TO区分の送信先が1件もない場合はエラーとして扱う
6. 成功: その行の送信ステータスを「送信済み」に、送信日時・送信回数を更新
7. 失敗: その行の送信ステータスを「エラー」に、発生日時付きのエラーメッセージを更新
8. 上記2の候補レコード取得自体が失敗した場合や、7のエラー状態書き戻し自体が失敗した場合、または前回以前の実行がGASの実行時間上限超過等で中断され「送信処理中」のまま残っている行を検出した場合など、個々の行のERROR_MESSAGEへ書き戻せない種類の失敗は、`ADMIN_NOTIFY_EMAIL`が設定されていればメールで通知する（未設定の場合はGASの実行ログにのみ記録される。同じ障害が続く間、大量送信を避けるため60分に1通まで）

## セットアップ手順

### 1. Apps Scriptプロジェクトの作成

```bash
cd customizations/reminder-notify/gas
npm install
npx clasp login
npx clasp create --type standalone --title "reminder-notify" --rootDir ./src
```

`clasp create` 実行後に生成される `.clasp.json`（`scriptId` を含む）は、`.gitignore` により追跡対象外です。`.clasp.json.example` を参考に、必要であれば手動で `.clasp.json` を作成してください。

> **既知の注意点**: 環境によっては`clasp create`が`.clasp.json`を`gas/`直下ではなく`gas/src/`の中に生成することがあります。その場合は`gas/src/.clasp.json`を`gas/`直下へ移動してください（`rootDir`の値はそのままで問題ありません）。

### 2. スクリプトプロパティの設定

Apps Scriptエディタの「プロジェクトの設定」→「スクリプト プロパティ」で、以下の**機密情報のみ**を設定します（フィールドコードは`src/Config.js`に固定値として定義済みのため、スクリプトプロパティへの設定は不要です）。

| プロパティ名         | 説明                                                                                                                                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `KINTONE_SUBDOMAIN`  | kintoneのサブドメイン名のみ（例: `example.cybozu.com`というURLなら`example`。`.cybozu.com`は含めない。含めてしまっても`.cybozu.com`が二重に付かないよう補正はされる）                             |
| `KINTONE_API_TOKEN`  | kintoneアプリのAPIトークン。「レコード閲覧」「レコード編集」権限が必要                                                                                                                            |
| `KINTONE_APP_ID`     | 対象アプリのアプリID                                                                                                                                                                              |
| `ADMIN_NOTIFY_EMAIL` | （任意・設定を強く推奨）認証失敗等、個々の行に紐付かないシステム全体のエラーが発生した際の通知先。顧客側はGASの実行ログを直接見られないことが多く、未設定だとこの種のエラーに気付く手段が無くなる |

### 3. デプロイ

開発中は`clasp`でこのリポジトリのソースをそのままプッシュする。

```bash
npm run push
```

**顧客先などnpm/npx/claspが使えない環境へ納品する場合**は、`src/`配下の複数ファイルではなく、1ファイルに結合した納品用ファイルを手動でApps Scriptエディタへ貼り付ける。開発側は責務ごとの複数ファイル+Vitestテストを維持しつつ、納品物だけを1ファイルにすることで、貼り付け作業の手間・ファイル作成漏れのリスクを減らす（[../CLAUDE.md](../CLAUDE.md)の「単一ファイルのカスタマイズ」と同じ考え方）。

```bash
npm run build
```

`dist/ReminderMail.gs`が生成される（`Config→KintoneClient→Mailer→ReminderService→Main`の順にファイル名区切りコメント付きで結合したもの）。Apps Scriptエディタの「コード.gs」の内容を全て削除し、この内容を貼り付けて保存する。詳しい手順は [../docs/GAS設定手順書.md](../docs/GAS設定手順書.md) を参照。

### 4. まずは手動実行でテスト（トリガー不要）

Apps Scriptエディタで`runReminderCheck`関数を選んで実行してください。初回は権限の承認が求められます。即時送信要求が立っているレコードがあれば、この時点で処理されます。

### 5. 自動実行のトリガーを設定

手動実行で問題なければ、`setupTrigger`関数を一度だけ実行します（引数省略で既定5分間隔。指定できる値は`1`/`5`/`10`/`15`/`30`のいずれかで、それ以外を指定するとエラーになる）。

```js
setupTrigger(5); // 5分間隔
```

内部で `runReminderCheck` に対する既存トリガーを削除してから作り直すため、間隔を変更したい場合も同じ関数を再実行するだけで構いません。

**送信タイミングは毎時00分/05分/10分...のキリの良い時刻に自動で揃う**（`setupTrigger`を何分に実行したかには依存しない）。実装上は常に1分間隔のトリガーを作成し、`runReminderCheck`側で指定した間隔の倍数の分でなければ即座に終了するようにしている（`isAlignedMinute`、[src/Main.js](./src/Main.js)）。実行間隔はスクリプトプロパティ`TRIGGER_INTERVAL_MINUTES`に`setupTrigger`が自動で保存するため、手動で編集する必要はない（間隔を変えたい場合は`setupTrigger`を再実行すること）。kintoneへのAPIリクエスト数は、この「揃え」の有無に関わらず設定した間隔と同じ頻度のまま変わらない（トリガー自体の発火が増えるだけで、間隔外は`UrlFetchApp`を呼ばずに終了するため）。

## 既知の制約

- Google Apps Scriptの1回の実行時間上限は6分です。対象レコード数が多い場合は、トリガー間隔や抽出条件を調整してください。
- `UrlFetchApp`・`MailApp` にはGoogleアカウントの1日あたりのクォータがあります（[Apps Scriptの割り当て](https://developers.google.com/apps-script/guides/services/quotas)を参照）。送信前に`MailApp.getRemainingDailyQuota()`で残数を確認し、不足していればエラーとして扱う
- トリガー間隔は、kintoneのAPIリクエスト数上限を考慮し、短くしすぎないでください（既定5分)。詳細は[ルートのCLAUDE.md](../../../CLAUDE.md#apiリクエスト数について)を参照。**精度と消費数はトレードオフ**で、1分間隔にすればより時刻通りに送信できるが1日あたりのAPIリクエスト数消費は5分間隔の5倍になる。5分間隔では、送信予定時刻から最大5分弱の遅延が起こりうる点を踏まえて間隔を決めること
- 1レコードに複数の送信タイミングがある場合、対象となった行の数だけレコード更新PUTが発生する（1行あたり最大3回: 処理中→送信済み、または処理中→エラー）
- GASを実行するGoogleアカウントの実行トリガーが1つだけ存在するよう、`setupTrigger`は内部で既存のトリガーを削除してから作り直す。同じ関数のトリガーを手動で複数作ると二重実行の原因になるため、トリガーの追加はこの関数経由でのみ行うこと
- `ADMIN_NOTIFY_EMAIL`未設定、またはスクリプトプロパティ自体の設定ミス（`loadConfig`が失敗する場合）は、通知先アドレス自体が読み込めないためメール通知できず、GASの実行ログでしか気付けない。初回セットアップ時に必ず[../docs/GAS設定手順書.md](../docs/GAS設定手順書.md)の手順で動作確認すること
- 送信タイミングをキリの良い時刻に揃えるため、トリガー自体は実行間隔の設定値に関わらず常に1分間隔で発火する。間隔外の実行は`UrlFetchApp`を呼ばずほぼ瞬時に終了するためkintoneへのAPIリクエスト数は変わらないが、GAS自体の起動回数（1日あたりのトリガー実行時間の消費）は増える。個人アカウントは1日あたりの合計トリガー実行時間の上限が90分のため、極端に処理が長引く設定と組み合わせる場合は注意すること
